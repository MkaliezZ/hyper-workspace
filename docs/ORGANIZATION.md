# 组织通讯录与产品组织管理

映射 P02/P04/P07/P08、C00/C03/C07、A01/A06/A10、E04/E09。公司身份与来源成员资格由 Nextcloud 负责，部门及产品角色由 Hyper Workspace 管理。部门关系不会授予项目、房间或文件权限。

## 输入与权威范围

企业连接只使用服务端配置的 Nextcloud 地址、工作区和成员组，以及当前员工经 Login Flow 验证的可撤销凭据。通过固定 Nextcloud 33.0.10 的公开 OCS 接口读取当前组成员，再以当前员工权限查询姓名；不使用 Nextcloud 管理员凭据绕过姓名可见限制，不直接读取来源数据库。

成员组最多 2000 人，超过明确拒绝，不截取前一部分当作完整组织。页面每次显示 30 人，按 UID 稳定分页；来源搜索最多 100 个候选，明确标记部分结果，并与当前成员组取交集。只处理 UID、可访问姓名和已验证的产品身份对应；不采集邮箱、电话、在线状态或其他 autocomplete 附加资料。来源不公开姓名时显示 UID，不用旧的产品缓存姓名替代。

产品员工 ID 仅对应已验证登录且仍为工作区成员的身份。尚未登录的来源联系人保持未映射状态，不自动建号、授权或加入项目。同名员工保留不同 UID。演示模式只读取演示工作区成员，页面明确标记演示来源。

读取后重新检查来源成员范围、当前产品权限和组织版本。来源失败、成员变化或撤权时整次查询失败；前端清除姓名、选择和编辑状态，迟到响应不能恢复旧目录。来源绑定摘要包括工作区、来源地址、内部传输地址和成员组；配置变化后旧部门关系和确认不能套用到新来源。

## 人工与 AI 操作

通讯录页面支持查找、部门筛选和分页；管理员可建立/更名/移动/删除部门、调整员工部门、修改已验证员工的产品角色。最多 500 个部门、20 层，拒绝循环及同级同名部门。删除前必须移走子部门和成员。角色变更需要另一位当前管理员执行，不能自行调整自身角色；来源管理员身份和权限不会因此改变。

所有写入绑定组织来源、预期组织 revision 和单独确认。角色还绑定员工 ID、预期角色、role revision 和本次 membership ID，撤权后重新加入也不能复用旧确认。后端重新核对当前管理员身份，不能采信请求中的 role 声明。

人工 POST /api/organization 与 AI 的 manage_organization / organization.manage 共用 OrganizationService。AI 只可提出一个空参数工具调用，具体部门、员工、角色和版本已由员工明确选择，模型不能更换。两个执行器使用同一契约；未提出要求的工具、伪造角色参数或多动作输出都不能成功。

AI 查询只保存范围、数量、时间和版本等回执元数据，不保存一份可绕过当前来源权限的联系人列表，也不广播模型生成的组织说明。当前姓名列表始终从通讯录入口重新核验。部门和角色写入有独立持久化审计、发起员工/设备引用、来源 Run 和幂等回执；不发送员工通知。

## 失败与恢复

组织变更在短事务内使用统一锁序：执行规则、组织范围、Run/成员及目标对象；来源网络调用在事务外。全局组织 revision 防止并发覆盖；同键同参数返回原回执，换参数拒绝。来源、身份或当前管理员权限失效时不能以旧回执再次授权。

写操作失去响应时页面保留原请求并冻结编辑，只能以原键核对/重试，不能悄悄替换目标。AI Run 可从产品执行状态核对和取消。取消阻止后续动作，不撤销已经提交的部门/角色变更。刷新后可查看“我的组织操作回执”最近 20 项已提交记录，并以当前目录和组织版本核对；只能读取本人、当前来源的审计回执，不以模型文本宣称保存成功。

## 迁移与回退

034_organization.sql 建立组织版本、部门、UID 部门关系、变更审计和 Run 计划；035_organization_membership_instances.sql 为每次工作区成员实例分配独立 ID。先备份、迁移，再更新 API/Worker/Web；无需更换现有模型或来源密钥。

回退前停止组织写入并核对活动 Run；保留组织关系、当前角色、成员实例与审计表。旧版本可忽略部门，但不得恢复旧角色覆盖已经确认的授权，或删审计伪装操作未发生。未接入 HR 系统、来源账号创建/停用、自动组织同步或公司组织规模验收；这些不能由当前目录入口推断完成。
