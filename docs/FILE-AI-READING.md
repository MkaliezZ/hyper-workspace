# 个人文件 AI 阅读与修订

对应 P02/P04/P05/P07/P08、C02/C04/C05/C07、A01/A04/A06/A08/A09/A10、E02/E04/E05/E07/E08/E09/E10 的子集。三层定义、默认 DSH、兼容 Hermes、资产与权限归产品核心的基线不变；固定场景的完整业务验收状态不因这些实现/测试改写。

## 员工流程与范围

完成 [Files 配置](NEXTCLOUD-FILES.md)，选择已导入且当前可读取的个人短文本，在预览中点“AI 阅读此文件”。选择 DSH/Hermes、chat 模型连接并提出问题；模型收到所选精确文件版本与问题。个人解读有稳定 ID，可人工修订、查看版本、停止后续执行；新结果从记录打开，已有编辑器不会被异步结果替换。重新打开页面可恢复当前版本的阅读记录与活动执行。

在一条已保存解读下填写“AI 修改要求”，沿用上方选择的执行器与阅读模型，点击“按要求修改解读”。AI 修改同一对象并追加版本；模型只接收这份文件、选中的已保存解读及原问题/当前反馈，不接收其他解读或完整修订历史。可以先由 DSH 生成，再由 Hermes 修改，下一次继续换回 DSH。

先保存手工编辑再交给 AI。执行期间仍可编辑、保存并接管；模型工作开始前或写入时发现版本变化就停止，不覆盖较新的内容。AI 完成后保留当前编辑框，员工主动“重新读取解读”才打开已保存的新版本；旧版本草稿保存遇到冲突时也保留在编辑框，不自动合并或更新它的版本基线。

该流程不需要 embedding，也不自动做跨文件召回。初次阅读只含一份显式选择的文件；续改额外含一条显式选择的当前解读。项目讨论、任务、其他个人文件、其他解读和未选择的旧版本不会混入上下文。解读保存在独立的个人对象与版本表，当前不进入通用关键词/向量索引或共享项目。共享发布、多文件阅读、文件选择/导入/建索引的 AI 工具仍待实现。文件到共享成果的权限传播尚未完成，不能标记全部 Files 或 C02/C04 验收完成。

当前文件限制仍为 64 KiB、18000 字符的有效 UTF-8 文本/Markdown；问题最多 4000 字符，解读/人工修订最多 20000 字符。每个导入记录最多保留 20 个解读对象，每个对象最多 10 个版本，失效记录也计入保留上限；保留期限与清理界面尚待实现。模型输入总大小仍受 100000 UTF-8 字节上限约束，原生输出上限 4096 token。

## 执行与数据契约

| 项目       | 规则                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| 来源/凭据  | 与 Files 相同：当前员工设备凭据、配置来源、fileid/ETag/解析结果版本；凭据由服务端解析                                       |
| 选择范围   | URL 中的个人资产 ID、显式 expectedSourceVersion；服务端核验当前文件与本人副本                                               |
| Run        | `read_file` 或 `revise_file_reading`；无 project/conversation；固定文件版本、actor、设备、模型和执行器；续改另存解读 ID 与预期修订版本 |
| 模型上下文 | 一份当前文件的标题/正文/版本引用及当前问题，来源内容作为待解释事实，不具有修改 Policy 的权力                                |
| 允许动作   | 恰好一次 `file.reading.save {content}`；来源、员工、接收人、项目和文件选择都不接受模型覆盖                                  |
| 产品结果   | 初次保存 v1；续改沿用同一对象 ID 并追加版本；每个 AI 版本绑定自己的 Run/执行器/反馈，原始生成 Run 与回执不改变；总结为固定完成文本 |
| 人工修订   | 与 AI 共用版本追加服务、锁与 expectedVersion 检查；不伪造 AI Run；版本上限 10、原生成回执保持 v1 |
| 失败/取消  | 无业务动作的失败为 failed；已保存动作后的中断进入 recovery_required。取消停止后续执行，已保存对象仍按当前来源权限读取       |
| 幂等       | 同主体/工作区同键同输入复用 Run，包括续改完成后用原预期版本重取原回执；同键不同问题/目标/版本/模型拒绝；新键按当前版本校验。动作按 Run+序号幂等 |

EngineAdapter 1.0 的能力表增加 `read_file`、`revise_file_reading`，统一提案工具为 `file.reading.save {content}`；目标由后端固定，模型不能覆盖解读/来源/员工 ID。引擎未声明对应能力时拒绝发起。原有项目工作流与上下文保持原行为。两个原生执行器使用相同 Run/工具/对象服务，运行中任务仍归原执行器；新任务可选择另一引擎，不迁移私有检查点。

两种文件工作流都需独立入口，普通项目 `/runs` 拒绝它们；数据库约束禁止挂载共享会话/项目成果、缺少文件版本或缺少续改目标/版本。引用采用 `file:<资产ID>@<来源版本>`，续改再记录 `file-reading:<解读ID>@<所用版本>`。每个版本的执行元数据只关联同主体/工作区/文件版本的 Run，错绑记录拒绝返回。引用证明输入版本，不代表已评价真实模型的引用准确性或中文质量。

## 权限、失效与运行目录

发起、Worker 载入、模型配置解析后的派发前、每个业务动作、最终状态提交及结果读取都核验员工/来源/精确文件版本。运行期间每 15 秒核验来源，取消与租约每秒检查。产品 API、版本记录、Run 与事件只对本人且当前来源版本仍有效时开放；产品 admin 不扩大可见范围。

文件源更新、删除、文件级撤权或明确不可下载时，文件失效事务同时清空全部相关解读版本、清空文件 Run 的问题/结果，并停止 queued/running 等活动状态。来源刷新即使恢复相同内容，也不会复活已经失效的解读；员工需显式重新发起。已经清理问题/结果的文件 Run 也保持不可读取，不因恢复相同版本而重新返回旧成功摘要。工作区成员或设备准入失败先阻断读取，统一停权清理与保留策略尚待完善。临时网络/5xx/限流仅拒绝本次访问，沿用 Files 的故障处理，不当作永久删除。

事件只保存通用阅读进度与对象回执，执行器原始进度与总结不作为个人正文副本持久化。原生执行所需输入只放在该 Run 的私有运行目录，正常完成/失败/取消后删除；终态及租约恢复时重试清理。崩溃到 Worker 恢复之间可能残留目录；这不代替生产容器隔离、加密磁盘、主机进程回收或备份清理。

网页沿用可见页面每 8 秒来源核验，失权后清空预览与编辑器；被关闭页面的迟到响应不能恢复旧解读。已经发送给模型的输入、员工复制内容和外部供应商保留无法由该模块撤回；Nextcloud 与 PostgreSQL 没有跨系统原子事务，不声称消除在途权限窗口。

## API 与迁移

- POST `/api/files/imports/:assetId/readings`：`{engine, instruction, expectedSourceVersion, modelProfileId?, idempotencyKey}`；返回 Run ID/state。
- GET `/api/files/imports/:assetId/readings`：当前来源版本的本人解读元数据与最多 5 个活动 Run。
- GET `/api/files/readings/:id`：本人当前解读、问题和修订历史，再核验来源。
- PATCH `/api/files/readings/:id`：`{content, expectedVersion}`，追加人工修订。
- POST `/api/files/readings/:id/revisions`：`{engine, instruction, expectedVersion, modelProfileId?, idempotencyKey}`，创建私人 AI 续改 Run；源文件/源版本由解读绑定，不接受客户端或模型覆盖。
- GET 解读的各版本增加 `runId/engine/feedback`，人工修订没有 AI Run；正文与反馈仍受本人及当前来源权限限制。
- 原 `/api/runs/:id`、events、cancel 复用执行状态/回执/取消服务；文件结果增加来源门禁。

迁移 `010_file_readings.sql` 增加文件 Run 绑定与二选一范围约束，以及个人解读/版本表。先迁移，再共同升级 API/Web/Worker。存在文件 Run 后，回退需要先停止执行与入口、核对已保存动作、清理私有运行目录和隔离文件解读数据；不能通过把文件 Run 改挂到共享会话或删掉绑定关系来兼容旧代码。优先向前修复，正式回退演练未完成。

迁移 `011_file_reading_ai_revisions.sql` 增加 Run 的续改目标/预期版本约束，以及逐版本的 Run 引用；仅为既有 v1 回填其已存在的原始 Run，人工旧版本保持无 AI 引用。没有复制或重建正文。升级前备份并停止新执行，先迁移再共同部署 API/Worker/Web。已有续改 Run 后，旧 Worker 不认识该工作流，不能降级执行或改挂共享会话来兼容；保留完整数据与引用，优先向前修复。Compose 管理员负责迁移，运行角色仍只写业务数据。
