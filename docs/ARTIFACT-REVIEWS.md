# 成果版本与员工验收

对应 P04/P05/P07/P08、C04/C05、A01/A08/A09/A10、E04/E05/E07/E09/E10 的子集。沿用固定产品基线和 EngineAdapter 1.0，默认 DSH、兼容 Hermes。验收是员工对具体版本的决定，不代表模型证明了成果质量，也不等于完整 E05 或上线验收。

## 员工流程

打开项目“成果”，检查已保存版本后选择接受、要求修改或重开，填写意见并勾选明确确认。可以直接记录，也可以选择 DSH/Hermes 与模型连接让 AI 代执行；两种入口进入同一产品服务。改变决定或意见后需要重新确认。

当前成果显示草稿、待修改或已验收。验收绑定确切成果版本与验收修订号；新意见不能覆盖未看到的并发意见。人工或 AI 保存新内容都创建新版本，重新成为草稿，旧版验收历史保留。当前并未实现完整“提交待验收”、指定评审人、多人会签或组织审批流程。

编辑框中的未保存文字与已保存版本分开显示，有未保存编辑时禁止发起验收。验收过程中仍可编辑；后台完成只更新状态和历史，不替换编辑框。版本冲突后保留文字，员工主动“重新读取成果”才替换为服务器内容；按钮旁明确提示会替换未保存编辑。关闭编辑器或切换项目后，迟到的请求不能恢复旧编辑器或旧 Run。

## 服务与数据契约

| 项目 | 规则 |
| --- | --- |
| 人工入口 | POST `/api/artifacts/:id/reviews`；严格计划与 UUID 幂等键 |
| 计划 | `expectedVersion`、`expectedReviewRevision`、`decision`、1–4000 字意见 `feedback`、`confirmed:true` |
| AI 入口 | POST `/api/runs`，`workflow=review_artifact`、绑定的 `artifactId/artifactReviewPlan`、引擎与模型引用 |
| 模型操作 | 恰好一次 `artifact.review {}`；不能传目标、员工、决定、权限或修改内容 |
| 模型输入 | 仅员工确认的计划与产品引用；不自动加载成果正文、项目讨论、企业文件或旧版内容；员工手填意见会发送给所选模型 |
| 权限 | 当前成果创建人，或有当前项目/来源访问权限的工作区管理员；管理员不绕过来源，身份来自服务端 |
| 记录 | `cw_artifact_reviews` 保存确切版本/验收修订、前后状态、决定、意见、员工/当时权限依据、设备凭据引用、Policy 版本、确认、直接或 AI 渠道与 Run 引用 |
| 当前状态 | `cw_artifacts` 保存 `review_revision/accepted_version`；已验收必须对应当前确切版本和存在的验收记录 |
| 历史 | GET `/api/artifacts/:id` 返回最近 50 条验收记录、当前可验收权限与内容版本；不返回设备凭据引用或任何密钥 |
| 回执 | 保存到实际业务记录后回读，AI Run 保存动作回执和 `artifact.updated` 事件；固定完成摘要，不把原始模型回复发布为项目消息 |

记录对当前项目获准成员可见；每个 Run 仍按员工隔离。个人文件 AI 解读不是共享项目成果，不纳入此入口。意见不进入向量索引；旧版记录通过外键保留关系，业务 API 不提供修改或删除历史的操作，但当前数据库运行角色仍有业务表 DML，不能称为防篡改审计系统。

## 并发、撤权与恢复

产品按成果行串行修改，同时检查当前产品成员及真实角色。内容版本与验收修订号分别作为并发门禁；相同幂等键和相同输入返回原记录，即使成果后来已有新版，历史回执仍指向原版本；不同输入复用同键被拒绝。每次读取/开始/动作与最终发布前沿用项目和当前来源权限核验；远程核验不置于长事务，也不能瞬时撤回已发送给模型的员工意见。

AI 不能重新选择决定、员工或成果。模型派发前和动作时核对版本；模型期间人工创建新版、并发新意见、取消或产品撤权都会阻止旧动作。验收记录、当前状态和动作保存同事务，故障全部回滚；动作已提交后进程中断仍沿用 `recovery_required`，取消不是删除已有验收。当前没有完整人工对账界面，遇到此状态需核对具体版本历史与动作回执，不能盲目重跑。

## 迁移、部署与回退

`014_artifact_reviews.sql` 增加验收表、当前验收字段和 Run 计划约束。旧成果保持草稿，旧版本/Run 不补造已确认状态。当前已验收版本通过复合外键绑定历史记录；验收与工作流/计划不能为空值伪装。

升级前备份并停止新任务和旧 Worker，管理员执行迁移及部署初始化，授予新表的受限运行角色 DML，再共同升级 API/Web/Worker。运行进程不获取管理员凭据。该未发布迁移开发期间，本机 localhost `hyper` 和隔离 `hyper_test` 已同步新增约束；新增权限依据字段前确认验收表为空，没有推断历史权限或清空数据。

已有验收数据后，不能运行会保留旧“已验收”状态但不清理新版标记的旧 Worker。回退应停止写入、核对 Run、保留历史和备份，优先向前修复；不通过删除验收行或去除约束掩盖状态。公司环境升级、备份恢复演练与正式回退尚未验收。

## 文档能力边界

项目成果目前仍是纯文本/Markdown 编辑、AI 反馈修订和版本记录；个人 Files 支持短文本/Markdown 导入、阅读与索引。尚无飞书式富文本、多人实时协作、批注评论、PDF/Office 受控解析或办公格式编辑。首版受控解析与后续在线协作分别推进，不因新增验收状态而宣称“文档功能完整”。C06 方法资产发布/复用仍待实现，验收记录仅提供其来源基础。
