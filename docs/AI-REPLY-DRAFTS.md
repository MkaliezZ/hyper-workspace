# AI 会话回复：起草、检查与发送

对应 P02/P04/P05/P07/P08，C00/C02/C04/C05/C07，A01/A03/A06/A09/A10，E04/E07/E09/E10 的子集。三层与技术基线不变：Policy 保留人的发送控制；功能分为生成、预览、编辑、发送和核对；产品保存私有消息草稿、来源引用及实际发送关系，两个执行器使用相同业务接口。

## 实际流程

1. 企业消息中选择已加入、可读取的会话，点击“AI 起草回复”。先打开或显式创建来源关联项目，再选择 DSH/Hermes 和模型连接，填写工作要求。
2. `draft_reply` 工作类型读取既有获准上下文，模型只能提出一个 `communication.draft`，参数仅允许 `content`（1–20000 字符）。会话、员工、项目与工作区由后端确定，模型不能指定接收者或发送消息。
3. Worker 保存个人草稿后返回“回复草稿已保存，尚未发送”。不会把该 Run 的模型总结写入项目共享讨论，不创建共享成果或知识索引。进程结束/页面刷新后，草稿仍能从“我的 AI 草稿”读取。
4. 员工预览后选择“放入发送框”；有人工内容时明确显示“替换当前草稿”。内容可编辑，生成与预览均不触发发送。
5. 员工点击“发送消息”后，复用 `CommunicationService` 的来源鉴权、幂等意图、发送、回读和未知结果核对。来源仍以员工真实身份显示作者，发送成功以实际回执为准。

这是 AI 辅助的回复闭环，**尚未提供 AI 自主投递、跨会话代发、批量发送或自动回复规则**。本功能没有给执行器开放任意通信工具；普通对话不会触发群内插话。用户已经选择“开始执行”后，生成过程不再逐步确认。

## 权限、数据与来源

草稿由 `cw_communication_drafts` 保存，稳定 ID、发起员工、工作区、来源项目、唯一 Run、正文、生成时间及输入引用独立于引擎。初版草稿为不可变的生成版本；编辑发生在发送框，未发送的人工修改只保留在当前页面；刷新后可恢复原始 AI 草稿。发送关系标记是否修改原稿，原始 AI 版本保留。草稿不是已发送 Message，也不是已验收 Artifact。

草稿只对同一产品员工本人开放；即使同在会话/项目、是来源群主或产品 admin，也不能读取别人的个人草稿。读取/列举/发送前仍检查产品资格、来源群组、当前设备凭据、Provider 实例、会话参与者和实际聊天读取权限。换一台有效设备可以读取自己的草稿；不会替换旧 Run 的执行凭据。

| 来源绑定字段         | 范围                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| connector / selector | 同一个来源关联项目及 Talk 会话，不接受模型自选目标                                                       |
| field / time scope   | 沿用 [项目来源契约](PROJECT-SOURCE-SCOPE.md)：最近一页至多 60 条普通消息及本项目记录，输入总字节上限不变 |
| credential_ref       | Run 固定发起设备；读取与人工发送使用当前设备的后端凭据，不进入草稿、向量或前端                           |
| access_policy_ref    | 个人所有权 ∩ 产品成员 ∩ 当前来源读取权限；发送另查只读状态                                               |
| update / provenance  | 每次生成新草稿 ID，保存本次来源版本/摘要引用；实际发送通过 draft_id 关联，draft_modified 标记用户编辑    |
| revocation           | 后台按既有项目规则复查；读取被拒绝后清理页面中的当前私有草稿/预览；失权不能读取、继续发送                |
| deletion / retention | 源编辑/删除不自动使旧草稿失效；提示生成时间供检查。草稿清理、保留期限及完整依赖失效链路尚待实现          |

只有原始生成草稿正文保存在草稿表。发送意图仍不保存实际发送正文；实际文字以 Talk 为准，产品保留参数/来源内容摘要、消息 ID 和回执。草稿不进入共享项目讨论、知识检索或 pgvector。所选模型可以接收已声明的上下文；真实模型质量、组织级模型外发白名单和 DLP 尚未验收。

## 重复、失败与恢复

- 同一个 Run 并发投递只保存一份草稿；文本声称“已发送”不会成为业务回执，模型总结被替换为产品确定的“尚未发送”状态。
- 发送时带可选 `draftId`，后端检查本人所有权及来源会话匹配。人工编辑改变幂等参数；重试仍须使用原键/原参数。
- 同一草稿已有 `sending/succeeded/recovery_required` 记录后，新幂等键也不能重复投递；索引与事务检查共同约束。明确失败的记录允许经用户再次提交。
- 未知结果复用原通信核对机制，不自动重发。人工“已查看来源，继续”不会把旧草稿改成已发送，也不能重新使用旧草稿 ID；页面将其转为新的人工发送意图。已发生副作用不能被取消回滚。
- 草稿列表仅返回本人当前会话最近 10 份元数据及发送状态，正文在预览时另取。已发送/待核对的草稿不能再放入发送框；页面切换及失权会丢弃过时的异步预览响应。

## 接口与迁移

- POST `/api/runs`：新增 `workflow=draft_reply`，必须是来源关联项目，`toolsForWorkflow` 只允许 `communication.draft`；DSH/Hermes 共同支持，演示会话不能借此访问企业来源。
- GET `/api/talk/rooms/:token/drafts`：本人最近 10 份草稿元数据，无正文。
- GET `/api/talk/drafts/:id`：本人草稿、来源引用及当前发送状态。
- POST `/api/talk/rooms/:token/messages`：原 `content/idempotencyKey` 保留；可选 `draftId`，不接收员工、Provider 或凭据字段。
- 迁移 `008_communication_drafts.sql`：新增个人草稿表、唯一 Run、来源项目外键；发送记录增加草稿关系/编辑标记与部分唯一索引。运行迁移后共同部署 API/Web/Worker，避免新工作类型由旧 Worker 消费。

回退前停止创建/消费新起草任务并核对在途人工发送。保留草稿与发送记录，不删幂等意图。旧版不提供新草稿入口，也不能回退到忽略 007 来源权限的代码；正式生产回退尚未演练。

## 核验证据

本地新增 4 项 PostgreSQL/HTTP 协议服务测试：个人隔离、未广播、来源引用、并发生成去重、编辑后回读、跨会话/他人借用拒绝、重复发送防护、未知结果/人工继续/只读核对、模型自选目标拒绝和执行中撤权。2 项 UI 协议测试覆盖生成入口到编辑发送、按会话草稿、原人工内容不覆盖、撤权后的清空与恢复。当前 9 单元、38 数据库、14 浏览器和 3 原生运行时检查已通过；新增真实来源联合用例待本次 CI。

真实来源 job 扩充到 7 项；新增用例使用固定 Nextcloud/Talk、独立测试员工、真正 DSH/Hermes 和本地模型协议服务，验证两个引擎生成本人草稿、不广播给项目/来源、群主也不可读取、人工检查后真实发送/回读、重复拒绝及来源撤权。该联合用例等待本次 CI；本机无 Docker/PHP，不将 UI fixture 当作真实来源证据。
