# 企业消息附件：接收、查看与受限下载

2026-10-30；P02/P04/P07/P08、C00/C02/C05、A03/A04/A05/A10、E02/E04/E07/E08/E09 子集。当前为接收链路增量，产品内上传、发送附件及其 AI 执行/未知投递对账仍待实现；不把此增量称为完整附件交付。

## 输入与来源

Nextcloud Talk 是消息/附件引用的权威，Files 是原文件的权威。仅解析固定 Talk `v23.0.12` 的 `systemMessage=file_shared`、`messageType=comment`、`messageParameters.file.type=file`。普通富文本对象不能变成可下载文件；删除/过期、格式不合法、源文件已不可用时不生成附件链接。

产品消息返回受限的文件 ID、名称、字节数、MIME、etag 与下载提示。源 URL、用户挂载路径、预览/联系人照片、分享口令及来源凭据不返回浏览器或模型。文件名/说明作为普通文本显示。附件是活文件引用，历史消息不是文件内容快照；文件更新或重命名后的信息以来源为准。

协议依据：[固定版本 Talk 文件解析器](https://github.com/nextcloud/spreed/blob/v23.0.12/lib/Chat/Parser/SystemMessage.php)、[官方 DAV 基础协议](https://docs.nextcloud.com/server/stable/developer_manual/client_apis/WebDAV/basic.html)。官方 stable 文档可能更新；运行组合仍按项目锁定版本，实际兼容性另以真实来源 CI 验证。

## 服务/API 与人工入口

企业消息显示附件卡片、名称、类型、大小与“在来源中查看”。启用企业文件服务且源允许下载、路径有效、大小不超过 8 MiB 时显示下载入口。更大文件、隐藏下载或未启用 Files 时交由来源界面处理。

`GET /api/talk/rooms/:room/messages/:message/attachments/:file/open?etag=...` 每次重新验证当前员工凭据、产品成员、来源会话、确切消息/文件 ID 与请求版本，再跳转到受信任配置的 `/index.php/f/:id`；不使用富对象传来的 URL，不创建公开分享，也不把产品凭据转交浏览器。来源可能要求独立登录，并自行执行当前文件权限。

`GET .../:file/download?etag=...` 在同一 `CommunicationService.attachment` 中额外执行：

1. 当前 Talk 下载策略与只读权限位；当前员工 Files 挂载路径经严格分段验证。
2. DAV stat 的文件 ID、etag、大小与 Talk 引用一致；etag 的 DAV 引号与节点原值作规范比较。
3. 条件 GET、来源响应 etag、实际长度、分块读取上限均核对；最多缓冲 8 MiB，不解压/解析附件。
4. 读取后重新 stat、探测实际读取权限，重读当前消息/附件和会话，再校验产品成员与连接未变化。中途删文件、撤权、隐藏下载或更改版本时丢弃缓冲内容。
5. 返回 `application/octet-stream`、`Content-Disposition: attachment`（UTF-8 文件名）、`nosniff`、`no-store`，不会在产品域内执行 HTML/SVG；查看跳转使用 `no-referrer`。

会话只读不阻止获准的读取；此处没有创建文件、改权限或发消息。读取前后的检查缩小竞态窗口，不能承诺源系统与产品的跨系统原子授权；已经交付到员工设备的字节无法远程撤回。

## AI 与资产生命周期

两个执行器经原有项目上下文服务取得同一范围的附件名称、文件 ID、类型和版本，并附“未读取正文，不得据文件名推断内容”。这只证明模型获得引用，不代表理解文件、OCR、视频或音频。显式 Files 导入/个人 AI 解读继续使用已有来源鉴权、解析和索引服务；此增量不会自动执行它们。

消息/附件读取不建持久副本、不写向量、不缓存正文，也不把下载内容放入模型、Run 日志或共享项目资产。房间轮询失败/移除、切换房间或卸载后沿用现有范围清理；旧卡片即使仍留在已打开页面，点击也必须经过当前后端检查。来源不可用时拒绝读取，不返回旧正文。

权限拒绝、删除/过期或错误文件 ID 返回 403/404；已知版本变化返回 409；无效输入返回 400；配置未开启或来源暂时不可用返回 503。读取失败可重试；此链路没有写入副作用，无投递恢复回执或后台盲重发。
