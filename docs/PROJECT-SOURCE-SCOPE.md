# 来源会话、项目与 AI 上下文

本增量保持既定三层与技术基线，对应 P02/P03/P04/P05/P07/P08、C00/C02/C03/C04/C05/C07、A01/A03/A06/A08/A10，以及 E04/E09/E10 的部分验证。Policy 决定“来源权限不能因 AI 或资产沉淀而扩大”；功能提供受限项目与上下文；资产记录项目范围、版本和引用，均由产品核心拥有，不依赖执行器私有状态。

## 使用与权限

企业账号在“企业消息”选择已加入的 Talk 会话，点击“项目空间”。已有项目直接打开；没有时填写项目名称、目标，创建一个关联项目。每个工作区/来源/会话只有一个关联项目，同参数并发创建返回同一对象。普通项目保持既有工作区范围；不能将已有普通项目改绑来源，也没有解除绑定或转为公开项目的入口。

项目的访问条件为：当前产品成员 ∩ 来源群组准入 ∩ 发起设备凭据有效 ∩ 同一来源实例 ∩ 当前员工仍在会话内 ∩ 当前能读取来源消息。产品 admin 不能绕过。除会话详情外，再进行最多一条消息的只读探测，避免“仍有成员元数据但聊天室读取已受限制”时泄露派生成果。探测不设置已读、清理通知或更新在线状态。

`ProjectAccess` 统一保护项目列表和直读、工作记录、待办、成果和版本、Run 内容与事件、关键词检索、向量索引及语义召回。SQL 在读取资产内容/召回前限定获准项目；索引在发送文本给 embedding 服务前检查，并在写入后端前复查，撤权时跳过写入。接口拒绝或来源不可用时不返回来源项目内容。授权检查和远端状态没有跨系统原子性，无法消除检查后的在途窗口。

项目“工作记录”保存在产品；原始 Talk 消息不导入项目消息表或共享知识库。新生成的成果及其资产副本属于该项目，即使资产内部标记 workspace 可见，仍须叠加来源项目权限。查看或回复原始会话使用“查看企业会话”。已发送给浏览器、执行器或模型的数据无法撤回；源编辑/删除不会自动删除既有派生成果，尚待依赖失效与保留策略。

页面在可见时每 10 秒刷新来源项目；失败后关闭私有编辑器、清理相关草稿及 Run 展示，切换至仍可访问的项目。主动切换项目也清空 AI 工作要求、成果选择、编辑和 Run 状态；讨论编辑器重新挂载，避免草稿跨项目。后台执行每 15 秒复查来源，并在模型派发前、每个业务动作前及最终发布前检查。来源失败会中止后续执行；已完成的业务动作保留，按现有 Run 恢复状态处理。原发起者可在仍有产品身份时取消自己的 Run，取消响应只有 `id/state`，不会借此读取已失权项目。

## 数据选择与来源引用

| 资产绑定字段      | 本次实现                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------- |
| connector         | 管理员配置的同一 Nextcloud Provider；凭据取当前设备服务端加密引用                           |
| object_selector   | 用户显式选择的一个已加入且可读取的 Talk 会话；绑定新项目后不可变                            |
| field_allowlist   | 会话 token/名称、消息 ID/版本、作者 canonical UID/名称、规范化纯文本；不读取附件 URL 或文件 |
| time_scope        | Worker 执行时来源最近一页，最多 100 条；仅其中最近至多 60 条普通 comment；无全历史导入      |
| access_policy_ref | 产品成员、来源群组、设备凭据、来源实例、会话参与者及消息读取权限的交集                      |
| sync_policy       | 每次执行实时读取，不永久镜像原聊天，不自动推进已读或通知状态                                |
| provenance        | Run `context_refs` 保存本次引用；成果版本继承旧引用并合并本次新引用                         |
| revocation_policy | 每次产品对象访问检查；执行中周期检查与业务动作前检查；不声称回滚已提交数据                  |
| deletion_policy   | 当前读取过滤源删除正文、过期消息；派生成果保留历史，自动失效/清除链路未实现                 |

来源引用格式为 `talk:<provider_key>:<room>:<messageId>@<editOrCreatedTimestamp>:<sha256(normalizedText)>`。摘要区分同一秒内的内容变化，不包含应用密码。产品讨论引用保持消息 UUID；修改成果另记录输入 `artifact:<id>@<version>`。这些引用说明使用过哪些输入，不证明模型逐条采用、事实正确或外部执行成功。

模型输入区分产品用户陈述、AI 草稿、系统记录和来源陈述；作者以来源 UID 标识，提示来源文本不能充当系统指令或已验证业务状态。产品工具仍由 workflow allowlist 与服务端执行，不因文本中出现指令开放原生任意工具。指令和上下文合计超过 100000 UTF-8 字节时在派发前失败；这是当前字节上限，不是 token/费用预算。

用户在发起任务时看到来源消息范围和所选模型连接。原始消息可能交给该模型处理；未实现组织级模型域名白名单、DLP、数据分类外发政策和真实模型质量评估。当前不会自动把 AI 结果发回 Talk；AI 写入通信须后续单独实现授权、幂等和回执。

## API、迁移与回退

- GET `/api/talk/rooms/:token/project`：当前来源权限验证后返回 `{project: 对象或 null}`，未关联时也提供有效 JSON。
- POST `/api/projects/from-talk`：严格 `roomId/name/goal`，主体与工作区由服务端确定。冲突名称/目标不改写已有项目。
- 既有对象 API 保持路径，新增来源权限保护。Run 读取增加 `contextRefs`；取消仅返回最小状态。
- 迁移 `007_project_sources.sql` 新增项目来源表、复合外键/唯一约束及 Run 上下文引用；不修改原项目权限，不搬迁聊天，不删除成果历史。

**已有来源项目后不能直接回退至忽略来源绑定的旧版 API/Worker。** 旧版可能把其内容当作工作区共享资料。优先兼容前向修复；必须回退时先停止对外 API/Worker/登录、隔离来源项目及其派生资产和历史、失效产品会话，并验证旧版所有读取/检索路径均不可访问后再开放。仅关闭 Talk 开关不足以保护不认识绑定表的旧代码；不要删绑定记录使项目降为共享。此回退流程还没有生产演练证据。

## 验证记录与限制

新增四项真实 PostgreSQL + HTTP 协议 fixture 测试覆盖：并发唯一绑定及 admin 越权、仅禁止聊天读取的权限、双重来源引用和成果修订、执行中撤权、撤权后的最小取消回执、关键词/向量/索引权限和 embedding 期间撤权、超限上下文在引擎调用前拒绝。原生运行时回归保留 DSH → Hermes → DSH 的产品资产版本和引用连续性。新增三项 UI 用例覆盖入口/模型范围提示、撤权后的编辑器/草稿清理、Vite 拒绝私有运行目录。

真实来源 CI 新增一个联合用例：固定 Nextcloud/Talk、独立测试员工、真实 pg-boss/API/Worker、真正 DSH 与 Hermes、本地模型协议服务，检查源消息确实进入两个引擎上下文、生成成果仅授权者可见，并在模型调用期间真实移除会话参与者后阻止业务写入。本机无 Docker/PHP，该联合用例等待本次 GitHub Actions 核验；不能将本地 fixture 记为真实来源通过。
