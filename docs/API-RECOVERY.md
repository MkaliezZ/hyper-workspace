# 空响应与服务恢复

2026-10-31。修复用户实际页面持续显示 `Failed to execute 'json' on 'Response': Unexpected end of JSON input`。P04/P07/P08，C00/C05，A10，E04/E07/E08/E10 子集。

公共 API 客户端原先直接 `Response.json()`；空响应/截断 JSON/网关 HTML 会暴露原生异常并遮蔽 HTTP 状态。当前统一读取并安全解析，401/403 等仍保留其状态；成功 HTTP 却缺少 JSON 回执按 502 处理，网络中断按 503 处理，显式 204/205 才视为无正文成功。错误正文和代理诊断不直接回显。Vite 开发代理连接失败返回结构化 503，不再只发空 500；部署代理的非 JSON 错误也由客户端处理。

写操作无法取得回执时提示先核对原状态，不自动重发。原有幂等键和业务对账仍是判断执行结果的依据，空响应不代表失败或未发生副作用。讨论发送失败保留输入草稿。

Run 轮询使用独立临时错误状态，同次最多一个在途请求。恢复取得当前 Run 后清除本次轮询错误，不清除其他操作的错误；旧 Run/卸载后的迟到响应不会更新当前页面。

已通过 2 个客户端单元场景和 2 个 Chromium 交互场景，含空响应、非 JSON/截断、认证状态、网络/正文中断、取消信号、写操作不自动重发、草稿保留、轮询恢复、桌面/手机布局及页面切换；类型检查通过。用户当前本机页面消息→设置→消息已核对，无错误横幅、框架遮罩或控制台错误。本修复包含在当前整批代码；实际来源/容器和对应提交的 CI 结果另行记录，不冒充真实供应商或公司验收。
