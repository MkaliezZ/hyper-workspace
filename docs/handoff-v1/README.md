## 当前产品定义

人表达目标，AI 帮助推进；讨论有沉淀，行动有回执，成果能修改，经验能复用。整个过程清晰、克制，并保留人的掌控感。

固定范围包含 8 条审美规则、8 组能力、10 种资产契约、10 个双执行器验收场景。审美层是公司的工作判断规则；功能层实现工作能力；资产层管理事实、内容、关系、方法与成果。

## 固定的技术路线

- React + TypeScript 自有 Web 界面；TypeScript + NestJS 自有业务核心。
- 模块化单体 + 独立执行 Worker；首版 Docker Compose。
- DSH 默认执行器，Hermes 必须作为兼容执行器验证，统一 EngineAdapter。
- PostgreSQL 业务与资产目录，pgvector 语义索引，pg-boss 后台任务。
- Nextcloud Talk / Files / Calendar 经通信、文件、日历 Provider 接入。
- 自有 PolicyService、RunService、ToolGateway、Asset/Knowledge 与 ModelProvider。
- 企业知识、身份权限、成果与执行回执归产品服务管理，独立于执行器私有状态。

具体组件版本、模型供应商、embedding 模型和企业实际数据源尚未配置。实施时依据兼容验证锁定，不能把设计选择报告为已运行功能。

## 完整性校验

安装 Python 3 后，在任意位置运行：

```bash
python3 "/交接包实际路径/verify_package.py"
```

脚本只读本包，不联网、不安装依赖、不运行应用。检查 SHA-256、必要文件、规格引用、本地链接及来源快照。路径移动或从 ZIP 解压后仍可执行。

- [MANIFEST.sha256.json](./MANIFEST.sha256.json)：所有负载文件的摘要，包含核验报告和核验脚本；清单本身不自校验。
- [SOURCE_SNAPSHOT.json](./SOURCE_SNAPSHOT.json)：原基线及历史报告的字节摘要。
- [PACKAGE_VERIFICATION.md](./PACKAGE_VERIFICATION.md)：本次打包、搬移和 ZIP 复核记录。
- [变更记录模板](./变更记录模板.md)：后续基线变更记录格式。

## 开始开发时的放置方式

把 AGENTS.md 放在目标开发仓库根目录，将其余规则文件保持相同相对结构一并放入。若仓库已有 AGENTS.md，应保留已有适用指令并合并本包规则入口；先核对真正的仓库路径和工作树。

如果将本包保存在仓库某个子目录，需要让仓库根部 AGENTS.md 显式引用本包并要求遵守。仅把规则压缩包放在旁边，无法让所有 Agent 自动发现它。

本包作为交接快照保存；开发进度、源代码与运行证据放到目标代码仓库。后续更改基线应生成新版本，并重建其清单与交接包。
