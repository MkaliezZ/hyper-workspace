2026-10-31，状态：本地开发批次已接通业务服务、人工/AI 入口、项目上下文和界面；本批次联合原生 DSH/Hermes 用例已通过，真实来源/容器及真实模型验收待完成。遵循冻结 C03“记录决定”、三层定义中 Message/Decision/Task/ArtifactVersion 分别建模的要求。映射 P01/P02/P04/P07/P08、C01/C02/C03/C05、A01/A02/A03/A06/A10；不把已有成果验收意见等同于独立业务决定。

## 产品行为

项目上下文显示当前已确认的关键决定，并可读取历史、修改依据、撤回或由新决定替代。每个决定有稳定 ID，属于确切项目；内容、状态、记录人、确认人、版本与来源分开记录。待办/成果通过稳定 ID 与决定建立关系，不将它们塞进聊天正文作为唯一业务状态。

人工可记录待确认提议、编辑及确认；AI 可从获准项目上下文整理提议，但提议不自动成为已确认决定。确认、撤回和替代由员工给出明确的目标版本与操作，可人工直接执行或让 DSH/Hermes 代执行同一业务服务。模型不能自行改变已确认的方向、伪造员工确认、选择另一个同名项目/决定或把“模型建议”写成“团队已决定”。

确认表示具名员工明确采纳这条业务记录，不等同于模型独立验证或额外组织审批。沿用当前项目权限；任何后续组织决策角色扩展须有实际配置与验证，不借工作区管理员角色越过来源会话。

## 数据与权限

业务主表由 PostgreSQL 拥有，保存 workspace/project/stable ID、current version/state、创建与确认主体、当前替代关系；追加版本表保存标题、决定正文、理由、状态、动作、主体/设备凭据引用、来源 Run 和时间。记录幂等与实际回读回执，不能由执行器私有记忆承担企业事实。

状态至少区分待确认、已确认、已撤回和已替代。编辑/确认/撤回均要求确切 expectedVersion；人工已编辑时拒绝迟到的 AI 结果。已确认版本保持历史；替代必须在同项目内，绑定新旧确切 ID/版本，原子更新双方并防止自引用与循环。不能用删除旧行掩盖历史决定。

来源记录使用产品已有 provider/room/message ID/源版本引用，避免存未经授权的历史正文副本。AI 提议必须继承实际使用的来源与版本；源变更/删除后不能继续把旧提议或引用当作当前证据。员工明确确认的业务记录与来源引文分别标明权威：原讨论只证明当时依据，不能据来源消失伪称业务已自动撤销，也不能继续展示被删除的原始引文。当前项目或源会话撤权立即拒绝对象、历史、关系和进行中的动作；派生内容与引用的清理沿用权限边界。

只有当前有项目访问权限的创建人或项目可访问的工作区管理员可修改/确认；人工与 AI 共用相同检查。创建人、确认人、参与讨论的人和待办负责人不能混为同一字段。项目成员当前身份来自真实 UID 映射，名字仅用于显示，歧义不能靠模型猜。

## 执行与界面

AI 整理提议使用受控写工具，只能生成待确认内容；管理操作绑定员工确认的计划并使用空参数工具，由服务端复核目标、权限、版本和有效规则。两个原生执行器使用同一契约；新运行从产品当前版本重建上下文，无需迁移私有检查点。

当前决定进入相关任务上下文时，只使用本次主体可访问的确切项目、当前状态和版本，并把提议/已撤回/已替代与当前已确认项区分。不能只靠同名或最近消息选择决定。与待办/成果的关系必须由当前可读对象核验，撤权后不泄露目标标题/正文。

项目区提供提议/当前/历史入口、可编辑内容和明确版本的确认/撤回/替代入口；显示谁记录、谁确认和实际状态，修改已有对象时保留员工未保存草稿，跨项目切换或失权清除私有编辑状态。蓝白黑样式与现有项目区一致，桌面/手机均可操作，不要求员工阅读引擎日志判断业务是否发生。

## 开发与验证门槛

依次完成迁移与版本化业务服务、人工 API、受控工具/双执行器、当前项目上下文与界面，再验证真实来源/容器及真实模型合成样例。API/工具/界面同步记录 README、IMPLEMENTATION、runtime-lock 和截图；不要仅交付一个没有使用入口的决定表。

回归至少覆盖：同键并发/换参数冲突、两个员工、跨项目/工作区拒绝、管理员仍受来源范围限制、旧版本与人工抢先编辑、撤回/替代关系原子性、模型不能伪造确认/改目标、DSH→Hermes→DSH 同对象续改、取消/租约丢失/撤权后不写、源引用变化与删除、页面迟到响应隔离、容器重启保留对象和历史。

迁移 `025_decisions.sql` 创建稳定决定、版本快照和幂等动作表；`026_decision_runs.sql` 为 `manage_decision` 绑定严格计划。人工使用项目 decisions API，AI 使用相同 `DecisionService`，前端项目“决定”页提供编辑、确认、撤回、替代及历史。当前已确认决定进入项目栏与常规 Run 上下文。任务/成果关系按确切版本保存。

决定来源核对消息 ID、版本和摘要。未确认草稿的来源失效时不返回旧标题/正文；已由员工确认的决定作为产品业务记录保留，并标记旧依据不可核验，不返回失效来源原文。项目/房间撤权后对象和历史均不可访问。替代同事务锁定双方版本，写入双方历史与动作回执，不能直接编辑已确认文本。

当前本地 9 个数据库/Worker fixture 场景和 2 个桌面/手机 Chromium 场景通过，涵盖原子替代、版本冲突、当前权限、来源变动、模型伪造参数、取消与迟到响应。协议模型不代表真实供应商质量；整批联合原生 DSH/Hermes 用例已通过（协议模型）；真实来源、容器重启和正式 E01–E10 待统一验证。
