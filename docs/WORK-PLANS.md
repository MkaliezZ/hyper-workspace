# 工作计划、消歧与执行确认

2026-10-31，P01/P02/P04/P05/P07/P08，C01/C03/C04/C05，A01/A02/A03/A06/A08/A10，E01/E02/E04/E05/E07/E08/E09/E10 子集。属于当前整批集成，不代替真实模型质量、公司试用或正式 E01–E10 验收。

项目“工作计划”提供“自然语言要求 → 候选步骤 → 必要澄清 → 可人工修改 → 确认当前版本 → 实际业务记录”。DSH/Hermes 共用产品保存的状态和业务服务。新任务可选择任一执行器；没有迁移私有检查点或无成本适配承诺。

当前计划一次支持最多 6 步：创建待办、修改待办字段/员工分配、创建成果草稿、完整替换确切版本成果。最多 6 个文字问题、60000 字符序列化计划。模型只能使用 work.plan 提交候选，不得发送消息、授予权限、发布方法或自行确认决定。其他功能继续使用已有受控工作流，没有因统一计划入口而移除。

## 目标和身份

模型给出名称与可选版本，不能提交自选 ID。后端在当前项目和来源范围内解析：同名员工、同名目标、没有精确匹配、旧版本或未完整提供原文时，要求员工选择确切 ID/当前版本。没有账号映射的来源参与者不能据名字自动分配。唯一匹配也先固定 ID 和版本，等待期间发生更改不能悄悄改用新版。

待办/成果目录超过 100 个时明确拒绝该通用入口，提示使用明确对象的原有修改入口；不会截取目录后声称名称唯一。模型上下文最多列 100 个成员，标记是否部分；实际消歧与提交使用完整受控项目成员目录（沿用 2000 成员边界）。来源与产品成员权限取交集，名字和模型文本不授予访问权。

讨论限于当前获准的最多 40 条记录。成果正文只有完整内容不超过 12000 字符、总正文预算不超过 30000 字符时才提供，否则明确缺失并要求员工查看当前原文后选择。替换操作展示完整候选正文及确切目标；原件版本和旧成果历史保留。

## 澄清与接管

Run 使用 waiting_input、waiting_confirmation。每次答案、选择和人工修改都推进治理 revision，旧确认不能重用。人工接管可修改步骤、正文、日期、负责人，删除或增加待办步骤；保存后重新核对，不直接产生业务副作用。

文字答案先作为员工输入记录。需要 AI 据此调整候选时，显式点击“根据已保存答案重新整理”，可能再次产生费用；新模型阶段只使用产品计划、答案、选择及重新核验的上下文。员工等待时间不计入主动执行时限，所有主动阶段累计受原快照和当前更严格规则约束。UTC 每日次数仍是 Run 数，供应商请求和费用逐次计入原请求账本。

重新生成前要求旧执行器目录已经清理，避免新阶段与旧进程收尾共用目录。当前员工在新设备重新登录后，显式重新生成会绑定后端验证的新来源凭据；旧设备的失效凭据不会被复活，每次修改/回答/确认都保存实际设备凭据引用，密钥不进入计划。新候选推进 revision，仍等待员工确认。计划自创建起 24 小时内有效；超时或来源失效必须重新核对，不自动执行。页面刷新可恢复本人近 20 条计划，跨项目/员工和迟到响应不能恢复旧私有内容。

## 确认、原子性和恢复

保存澄清与最终执行确认分开；包含新答案/选择的请求不能同时确认。确认阶段不再调用模型。后端重新检查当前成员、来源绑定/凭据、讨论版本、目标版本、员工映射、规则与动作上限；固定锁序后，在同一 PostgreSQL 事务内写本批业务对象、资产、版本、动作和最终回执，任一步失败整批回滚。状态标记不代表实际工作独立验收，也不声明已经通知负责人。

幂等键与确切请求/计划 revision 绑定。响应丢失后只核对原请求，不自动用新键重复创建。取消阻止后续确认；已提交的记录不会被取消假装回滚。远端来源检查与产品事务不是跨系统原子提交，后续操作仍重新检查来源。

API：GET /projects/:id/work-plans 仅列本人元数据；GET /runs/:id/plan 读取当前计划；POST /runs/:id/plan/responses 保存回答/选择、明确重新生成或单独确认；PATCH /runs/:id/plan 人工接管。执行经现有 Task、TaskAssignment、Artifact 服务，不由模型文本宣称完成。原始模型进度换为受控状态，私有运行目录在结束和对账时清理。

## 迁移和证据

迁移 031_work_plans.sql 创建产品计划、版本、幂等回执与等待记录；032_work_plan_phases.sql 支持多轮等待/模型阶段，033_work_plan_audit_indexes.sql 增加当前设备凭据审计与计划列表/回执索引。先迁移再更新 API/Worker/Web；不新增服务、供应商或 Key 格式。回退前停止计划入口、取消/核对待执行计划并保留历史/回执，不删除业务记录或复活旧确认。

本地 8 个数据库/Worker 场景和 2 个桌面/手机场景通过，覆盖同名/旧版本、生成期间人工修改、分阶段回答、模型续写、人工接管、原子回滚、回执重放、等待时限及当前限制。真实 DSH/Hermes 的整批联合用例也通过，模型是本地协议服务。首轮界面回归发现刷新后列表延迟，已修复初始化请求失效问题并原场景复测通过，首轮 trace 保留在本机受限运行目录。

整套 5 个真实执行器场景已本地通过（协议模型），审计补充后又复测 8 个数据库/Worker 场景及整批原生联合场景。修正后完整 56 项 Chromium 界面回归通过，无重试；新增固定 Nextcloud/容器用例随本批提交核验。尚无完整自然语言质量、所有指代类型、超过当前边界规模或公司环境验收结论。
