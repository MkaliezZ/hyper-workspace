# 真实模型双执行器业务检查

日期：2026-11-01。状态：**合成样例的技术回读通过，正式公司验收未完成**。固定三层、首版范围、E01–E10 和原快照均未修改。

## 场景与证据边界

沿用用户指定、已经在产品加密保存的 DeepSeek Flash 个人 chat 连接，经正常 ModelGateway、Policy 和用量记录调用实际供应商；DSH/Hermes 均为仓库锁定的原生执行器。未复制 Key、修改价格或放宽实际连接的规则/预算。输入为两个互相独立的合成项目，各有相同的三条来源消息；来源是 loopback HTTP Talk 协议 fixture，并非真实 Nextcloud 或公司资料。真实 Nextcloud 的权限验证另看 CI，不能拼接为同一公司全链路。

每个项目都明确：

1. 2026-11-01 合成讨论：operator 提交内测清单，截止 2026-11-04；peer 完成风险表草稿，截止 2026-11-05；初始均未完成。
2. 发布审批尚未获得、DNS 问题尚未确认；不得写成已上线。
3. 只保存一份纪要和上述两条待办；这是合成样例，不是公司真实会议；没有外部群组发送决定。

生成纪要和待办后，脚本作为测试操作者，分别明确选择两个 seeded 员工 UUID，调用独立的 `assign_task` 确认计划。模型没有从姓名猜测员工 ID、扩大权限或发送通知。另一执行器在相同成果 ID 上续改为“结果、负责人、下一步、风险与未知”四部分。随后使用第一项目做静默/合并提醒检查。

## 首轮失败与修正

- 第一轮共 5 次实际请求。Hermes 把截止日期写入标题，实际任务 dueDate 为 null，原日期字段断言失败。产品工具指导原来只说明 title/assignee；现补充 dueDate 的 YYYY-MM-DD/未知为 null、保留来源年份及负责人文字与员工 UUID 的边界。没有增加从标题猜日期的补丁，也没有删除日期断言。
- 第二轮共 4 次实际请求。Hermes 续改已保存 v2，但一条流式用量是 unknown/partial；脚本把每条用量都要求 reported，因而中止。修正为分别检查业务回执和传输/用量状态，保留不完整用量；没有将它伪报完整，没有更改产品统计采集，也未放松任务日期/身份/版本/静默断言。
- 最后一轮 14 次请求完成上述业务回读，其中 1 条用量不完整。三轮合计 23 次供应商请求，都保留实际流水，不能只计算最后的 14 次。首轮输出/报告保留在本机受限且忽略的目录中；不提交私有运行目录或凭据。

## 复用检查脚本

脚本 `scripts/real-business-smoke.ts` 默认仅输出预检说明，不连接数据库或发送供应商请求。它是开发/管理员测试入口，不是员工操作流程。

```sh
node --import tsx scripts/real-business-smoke.ts
```

实际运行需要本机 `.env`、已初始化的 demo workspace/员工、已安装的固定双引擎，以及该 demo 员工本人拥有、在设置页配置验证好的 DeepSeek Flash chat 连接；禁止把 API Key 填为连接 ID。脚本限定 seed workspace/owner、供应商 endpoint/model，不会自动新建或复制真实模型连接。

```sh
REAL_MODEL_PROFILE_ID="existing-demo-chat-profile-uuid" node --env-file=.env --import tsx scripts/real-business-smoke.ts --execute
```

真实执行可能计费。仅在已授权的模型/测试范围内使用，先核对供应商价格和现有产品规则/预算；脚本不修改或绕开限制。每轮新建受限、忽略的私有报告目录，使用新的独立合成来源；保留真实产品对象与流水，结束时清空临时来源并禁用合成凭据，不删除用户的模型、偏好或账目。不应拿它直接检查公司生产资料。对失败的 Run 先查实际回执，不通过自动重放未知操作来凑通过次数。

本次实测使用此公开脚本的前身私有版本；公开版本保留相同业务断言，并增加通用连接 ID 参数、唯一私有输出、预检/错误脱敏与清理诊断，以及最终状态复查。公开版本已完成无请求预检和静态检查，未另行重复计费调用。模型输出具有非确定性，后续复测失败必须保留，不能据此承诺任意输入都得到相同结果。
