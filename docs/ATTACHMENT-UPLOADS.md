# 本机附件上传与后续 AI 分享

2026-10-31；P02/P04/P07/P08、C00/C02/C05/C07、A03/A04/A06/A10、E01/E02/E04/E07/E08/E09/E10 子集；不改冻结规格。上传原件权威仍是 Nextcloud，持久意图与回执归产品，不引入第二个文件存储或执行器私有资产。

## 员工路径与 AI 边界

企业消息 → 发送附件 → 从本机选择单个 1 字节至 8 MiB 文件 → 确认保存到自己的 Files → 上传并选中 → 再确认会话/说明 → 直接或 DSH/Hermes 发送。保存和投递是两个可检查的动作，不将上传成功、Run 排队、来源消息投递、员工已阅读混称为成功。

上传是员工提供文件输入的步骤。引擎不遍历本机文件、持有源凭据或接收原始字节；上传后的确切 Files ID/ETag 进入既有 `attachment.share` 确认方案，两引擎共用 [发送服务](ATTACHMENT-SENDING.md)。若要让模型解读正文，仍需通过个人文件导入/AI 阅读的独立授权路径；这次分享不会自动索引或将正文放入向量。

原件保存在当前源 UID 自己的 Files 根目录，名称为 `意图 UUID--原文件名`，避免覆盖同名原件；不接受客户端指定 DAV URL、其他人的根目录或执行器工作目录。原件遵守来源后续共享/修改/删除权限，不声称能撤回离线副本。关闭窗口、停止 AI 或放弃尚未投递的分享都不自动删除已经上传的原件。

## 接口与持久性

`POST /api/talk/attachment-uploads` 接收严格 schema：当前 roomId、文件名、size、sha256、confirmed=true、UUID idempotencyKey。文件名必须是单个路径片段，最长 160 字符且 UTF-8 最多 180 字节；空文件、超限、路径穿越及额外字段拒绝。数据库先持久化 `prepared` 意图，不包含字节、Key 或下载口令。

`PUT /api/talk/attachment-uploads/:id/content` 只接受 `application/octet-stream`、无 content-encoding、匹配确认长度与 SHA-256 的原始字节。原始解析器仅挂到此端点；先认证及检查意图所有者、当前源身份/房间，再读最多 8 MiB。其他 JSON 请求限制保持原样。字节仅存在有界请求内存，不存数据库、日志、执行器目录或临时磁盘；进程重启不会悄悄续传。

在工作区/有效凭据校验与短事务 CAS 后，`prepared → uploading`，持久 attempted_at，再在事务外发一次带 `If-None-Match: *` 的条件 DAV PUT。并发请求只有一次获得派发；同键换文件冲突，重放旧上传不再 PUT。标准 412 记录目标已存在、没有覆盖，不自动采纳现有文件。

成功须回读当前路径的文件元数据、ETag 条件二进制内容及 SHA-256，再次核对 ID/ETag/长度、当前房间及产品/来源身份后保存 `succeeded`。这证明已观察到所选字节的原件，不证明已经发送会话。没有可靠回读、断网或派发后撤权记录 `recovery_required`，不能当作没有写入。45 秒未完成的 uploading 也进入待核对。

`GET /api/talk/rooms/:room/attachment-uploads` 为当前员工的近 20 条记录；`GET /api/talk/attachment-uploads/:id` 返回本人回执。已成功原件若发生变化、删除或不能读取，历史上传事实仍在，但 file 为 null，不能用旧版本继续分享。旧凭据失效或房间撤权后不能读取这些私有记录；重新获得相同源 UID 的合法身份后可核对。

`POST .../:id/reconcile` 只读原件、校验字节和版本，不再 PUT；404 或摘要不匹配保持未知。`POST .../:id/release` 对 prepared 只放弃未开始的上传；并发派发 CAS 获得执行权后不再被改成“没有上传”。对 recovery_required 只标记员工已查看来源，解除本房间新上传阻塞；未知状态保留，不删除原件、不宣称已撤销。重选文件建立新意图时仍需明确确认。

## 部署、回退与限制

应用 `024_attachment_uploads.sql` 后更新 API/Web；Worker/引擎接口沿用已有文件分享契约。无新运行服务、依赖或密钥格式。反向代理上传限制应允许原始请求 8 MiB；超限直接拒绝，不用扩大所有 JSON 请求限制。

回退前停止新上传、核对 uploading/unknown 原件，保留新表和来源文件；旧版可以忽略新上传表。不能 DROP 意图来掩盖已经发生的写入。已确认的上传原件可通过既有 Files 选择器继续使用。

当前不支持多文件/分片/断点续传、后台保存本机字节、任意目标文件夹、覆盖原件、自动删除补偿或跨 DAV/OCS 的原子上传与投递。不承诺严格一次外部副作用、原件永久不变、恶意源服务下的写入归属或公司生产容量。原件接入和分享受当前员工权限约束；真实公司与模型效果仍须验收。
